# 利用ガイド

[本番サービス](https://hiyori-schedule.com) · [使い方ガイド](https://hiyori-schedule.com/help)

## イベントと候補日時

主催者はタイトル、説明、既定所要時間、候補日時、回答締切を設定する。候補は開始時刻が必須で、終了時刻を省略すると既定所要時間から補完される。参加者の回答を集計し、主催者が候補を選んで開催日を確定する。

## 公開イベントと招待限定イベント

イベントの既定の公開範囲は `public`（公開）。公開イベントはリンクから閲覧でき、Web では表示名だけでゲスト回答もできる。閲覧・回答を制限する場合は `invite_only`（招待限定）を選ぶ。主催者と招待された Discord アカウントだけが閲覧・回答でき、ゲストは参加できない。

- 新規招待には Discord の**ユーザー名**を使う。表示名、旧形式の `name#1234`、数値の Discord ID ではない。先頭の `@` は任意で、前後の空白・英字の大文字は正規化する。数字だけの入力もユーザー名として扱う。
- 相手が Hiyori 未登録でも招待を保存できる。イベント URL を別途共有し、相手が Discord にログインしてアクセスすると、サーバーが現在のユーザー名を Discord に問い合わせて招待をアカウントに結び付ける。既にログイン済みなら再ログインは不要。
- 最初の照合時点でそのユーザー名を持つアカウントが対象になる。受取り前の改名や入力間違いに注意する。一度結び付くと、以後の改名で別アカウントへ移ることはない。
- Discord の一時的な障害・利用制限や Bot トークン未設定時は新しい招待を照合できない。少し待って同じページで再試行する。既存セッションと受取り済みの権限は維持される。アクセスできないイベントは不存在と同じ 404 表示になる。認証自体が無効な 401 では通常のログインが必要。
- 招待の一覧・追加・取消は主催者のみ。未受取りと受取り済みを合わせて最大 500 件。取消は一覧にある招待レコード ID を使う。削除した招待は後のログインで復活しない。
- 公開イベントに招待を追加しても公開範囲は変わらない。制限には公開範囲の変更が必要。公開へ戻しても招待は保持される。

[CLI](../cli/README.md) では `event create --visibility invite_only --invite-username friend_one`（タイトル・所要時間・候補日時も必須）、`event edit EVENT_ID --visibility public|invite_only`、`invite list|add|revoke` を使う。

[MCP](integrations.md) では `hiyori_create_event` の `visibility` と `invitedDiscordUsernames`、`hiyori_edit_event` の `visibility`、`hiyori_list_invites` / `hiyori_add_invite` / `hiyori_revoke_invite` が対応する。作成時の初期招待には `visibility: "invite_only"` が必須。イベント・候補・初期招待はまとめて保存する。

これらはこのリビジョンの Worker と CLI の機能。プレビューへの反映だけでは本番 MCP や手元の CLI は更新されない。

## Discord 通知

本番トップページの「Discord サーバーに追加」から Bot を追加し、通知先チャンネルで `/hiyori new` を実行する。返されたリンクからイベントを作ると、そのチャンネルに連携する。

**通知はチャンネル連携した公開イベントが対象。招待限定イベントは通知しない。** 通常の Web 作成、CLI、MCP で作ったイベントはチャンネル未連携になる。Web の編集画面では通知先の付け替え・解除は行わない。通知先を変えたい場合は `/hiyori new` から作り直す。

独自に Bot を構築する場合は [Discord Bot 構築](discord-bot.md)を参照。

## カレンダー連携

- **個別の `.ics`**：確定日をファイルとして取得し、Apple Calendar など iCalendar 対応アプリに追加する。API は `GET /api/events/:id/decision.ics`。招待限定はログインと閲覧権限が必要。取消済みの確定履歴も取消情報として含む。ファイルの一度の取り込みは Webcal 購読とは異なり、継続的な更新を保証しない。
- **Webcal 購読**：マイページで自分用 URL を発行し、カレンダーアプリに登録する。API は `GET /feeds/:filename`。自分が参加した公開イベントの有効な確定日をまとめて配信し、招待限定は含まない。イベント単位の購読ではない。反映時期はカレンダーアプリの更新間隔による。
- 購読 URL はログインなしで取得できるフィードへの鍵になるため、公開資料に載せない。URL は新規発行・再生成時だけ表示され、一覧では復元できない。再生成すると旧 URL は無効になるためカレンダー側も登録し直す。
