## 承認済み範囲（2026-10-25）

対象は既存 Worker `hiyori-e2e` とその専用資源だけ。本番 `hiyori`、main、修正 PR #125 は対象外。既存 Cloudflare 接続と Builds を使い、別サービス、API キー、認証フロー、課金プラン変更は追加しない。権限不足なら停止し、対象権限を報告する。

| 設定 | 承認した値・範囲 |
|---|---|
| `env.e2e.ai.binding` | `HIYORI_AI`（継続する Workers AI 能力を e2e に追加） |
| モデル | コード固定の `@cf/qwen/qwen3-30b-a3b-fp8` |
| `HIYORI_AI_ENABLED` | `"true"`。失敗時は `"false"` にして推論を止める（同じ e2e の設定だけを変更） |

予算の単位は USD マイクロドル（1 USD = 1,000,000）。これはアプリ内の保守的な開始予約であり、Cloudflare アカウント全体の請求を止める機能ではない。予約は毎回入力32,768・出力1,024トークンを基に行い、現単価では2,015マイクロドル。入力サイズ上限は schema を含めた JSON の UTF-8 バイト数 + 2,048 で判定する。バイト数を課金トークンと同一視しない。無料枠・他アプリの消費・プランの残量は未確認。価格改定、税、他の Worker/D1 利用料金は別。日次/月次は UTC 境界で再計算する。

機能有効化後の利用者は既存のログイン済み e2e 利用者。1人5回/直近60秒・30回/UTC日と全体予算を適用し、送信内容の確認を求める。既存予算台帳の残高を読み取り、既存データや予約は消さない。e2e は cron 無効なので、推論受付時にも今月・前月より古い台帳を削除する。無利用中の定期削除は行わない。

## 送信内容と保存

送るのは入力した直近最大6メッセージ（各最大1,000文字）、定型の案内指示、現在日付とブラウザのタイムゾーン。既存イベント・投票・招待一覧、本人の Discord ID、Cookie、トークン、ページ URL は送らない。ただし本人が会話に書いた文字列は送信されるため、秘密や個人情報は入力しない旨を表示する。

会話はタブ内メモリのみ。アプリの DB・URL・localStorage・本文ログには保存しない。費用台帳には UUID、本人の Discord ID、予約額、時刻を保存する。通常の同期推論のみを用い、AI Gateway、キャッシュ、バッチ、ファイル保存は追加しない。[Cloudflare のデータ方針](https://developers.cloudflare.com/workers-ai/platform/data-usage/)では通常推論の本文の原則非保持・学習不使用を説明しているが、運用メタデータと法的例外は区別する。

## 実モデル試験（8回で終了）

最大**8回**、再試行を含めて数える。1回の実出力は最大1,024トークン。入力はアプリの `inputBound <= 28000` を維持する。費用比較は余裕を見てモデル文脈長32,768を毎回の入力トークンとして計算し、合計入力262,144・出力8,192で **約USD0.0162**。承認した追加試験予算は USD0.02。公式 AI 実行 API を直接使う合成試験はアプリの D1 予約を自動では通らないため、通常 e2e 利用枠とは別の8回限定の検証枠として承認・計数する。試験枠と通常利用枠を合算した枠は USD0.12/UTC日・USD1.02/UTC月。これは料金前提による概算・開始制御で実請求の保証ではない。失敗・結果不明も呼出数を消費し、アプリ経由なら費用予約も残す。自動再試行はしない。追加試験は別途確認する。

試験内容はすべて合成データで、(1)日本語の短い会話、(2)具体日時の公開イベント下書き、(3)相対日付、(4)月末・年越し、(5)曖昧な日時への聞き返し、(6)公開範囲不明時の聞き返し、(7)指示逸脱入力からの権限拡大防止、(8)下書き修正の会話。現在日付・タイムゾーンを固定した合成ケースを用意する。実イベントの保存・招待・確定はしない。ケースID、成功/失敗、処理時間、使用トークン等だけを検証記録に残す。日本語の自然さ・日時の正確さ・schema 受理を個別に判定する。

モデルページには `response_format` がある一方、JSON Mode 対応一覧には Qwen3 が掲載されていない。最初の実呼出しで現行形式を確認し、不正出力・非対応なら停止して修正する。別モデルや JSON 検証の省略に黙って切り替えない。

実測結果: 初回の JSON object は `draft` 欠落で不受理。JSON Schema 指定に修正後の7回は受理。入力5,013・出力528トークン、合計概算USD0.000432543。8回の最大出力は各1,024。8回を最悪条件で比較した予約額はUSD0.01612。実請求は未確認。追加推論を行わない。日本語会話、具体日時、相対日・年越し、曖昧さへの質問、指示逸脱拒否、下書き修正を確認し、公開範囲欠落だけの独立ケースと夏時間等は今回未実施。

1. 承認した金額・継続アクセス範囲を記録し、公式料金と既存接続の権限、e2e 専用 DB の migration/予約残高を読み取り確認する。
2. 接続・設定は `env.e2e` だけに追加し、型・モック・全検証、exact commit の CI/Security を確認。既存 Builds の guard は「AI なし」から「承認した e2e binding と予算だけ」に具体化し、専用資源・commit/tree の固定は維持する。
3. 既存 Cloudflare 接続から承認枠8回の中で公式 AI 実行 API に合成入力を送り、実際の返答を既存 parser と日付/schema の検証へ通した。これはモデル実測であり、e2e Worker binding や公開 HTTP 経路の成功を証明しない。D1 予約・認証・本人確認・フォーム受渡しはローカル Hono とモックで独立検証できる。8回を消化したため追加推論はしない。
4. 承認された設定で e2e へ反映し、binding・予算設定、配信版、資産を確認する。実際の e2e の認証済み API から推論・下書き受渡しが通った証拠が得られるまで全体は未完了とする。
