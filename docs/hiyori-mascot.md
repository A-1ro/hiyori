# ﾋﾖﾘﾁｬﾝ 初期版

キャラクター原画と最新の PC／スマホのローカル画面は [デザイン確認](design/hiyori/README.md) を参照。UI はサイトの実効テーマに従い、OS dark だけで単独の配色にはしない。スマホの起動 UI はページ内配置、直接の非表示×は44px。本体を非表示にしても共通フッターの設定から再表示できる。

単一Worker内のサイト内エージェント。使い方案内・ミーム・表示設定は推論不要。業務操作は既存MCPと共通の22ツールを使い、別のOAuth接続や新サービスは追加しない。既存REST/MCP/CLIの業務契約・認可は維持する。対応表と送信範囲は [ツール対応表](hiyori-agent-tools.md)。

## 構成と本人確認

- `src/server/tools/hiyori-tools.ts`：既存22ツールの定義とAPI呼出し処理。`mcp/agent.ts`は従来のOAuth権限・read/write scopeを渡す。`tools/catalog.ts`は同じ定義からJSON schema・厳密な引数検証を作る。
- `src/server/tools/session-api.ts`：サイト内では既存Webセッションで同じHono APIを呼ぶ。実行コンテキストを保持し、確認後の通常通知を落とさない。モデルにCookie・トークン・ユーザーIDを渡さない。
- `src/server/services/hiyori-agent.ts`：ユーザー発話から意図と使用可能ツールを絞り、最大3推論・各応答最大2ツール。全バッチを検証してから読む。更新要求は確認提案を返して終了する。回答を新規作成に変換しない。ISO8601オフセットをUTCに正規化し、共通schemaを通す。
- `src/server/services/hiyori-actions.ts`：認可済み対象・本人回答等の変更検知、既存セッションでHMAC署名した5分の確認情報、一度だけの実行。確認時も最新状態・同じ本人・既存API認可を再検証。結果不明は再送しない。
- `src/server/tools/web-agent.ts`：`POST /api/hiyori/agent/{chat,read,prepare,confirm}`。同一Origin・JSON・WebセッションCookie・本人一致を必須にし、CLI/BearerセッションをWeb権限として昇格しない。読取APIから更新しない。既存`POST /api/hiyori/chat`は旧入出力契約を維持する。
- `src/client/components/HiyoriOperations.tsx`：対象選択、候補と既存回答、○△×・コメント訂正、集計、主催者の確定、内容確認と明示送信。招待一覧・購読URL等はアプリ内表示。`Hiyori.tsx`は会話・アカウント・非表示設定を管理する。
- 新規作成の候補が既存フォームの日付×時刻へ情報を失わず変換できる場合、`EventCreatePage.tsx`への下書き受渡しも使える。それ以外は全候補を確認カードへ表示する。

モデル入力は直近最大6メッセージ（各1,000文字）、今日とタイムゾーン、選択・送信確認済みの対象イベント名・候補日時・本人回答・集計だけ。実IDは`selected`と`slotN`に置換。無関係イベント、他参加者の個別回答・名前、招待先、購読URL、認証情報をモデルへ返さない。イベント文字列を命令として扱わず、出力はHTMLとして解釈しない。サーバーの意図制限・引数検証・認可・本人確認が最終的な制御であり、プロンプトだけに依存しない。

会話・対象・下書き・確認情報はタブ内メモリだけ。localStorageは表示設定だけ。ログアウト・アカウント切替・消去・非表示で処理を中断し、遅延応答も破棄する。対象イベントを切り替えると前の対象の会話を消去する。パネルを閉じるだけなら残る。確認後の業務データは通常どおり保存される。

`hiyori_action_receipts`は確認UUID・本人ID・内容ハッシュ・処理状態・時刻だけを持つ。原子的INSERTで確認の再使用を拒否。引数や本文を保存せず、24時間より古い記録は次回確認時に削除する。migrationは`0016_familiar_molten_man.sql`。2026-10-25に既存Cloudflare接続でe2e専用DBだけへ適用し、既存イベント数の不変を読み戻した。本番は未適用。無操作中の定期削除はしない。

## e2e 限定の接続と安全な停止

2026-10-25 の承認に基づき `wrangler.jsonc` の `env.e2e` だけに `HIYORI_AI` binding と下記設定を追加する。本番・既定ローカル環境には追加しない。予算・料金の未設定、DB migration の未適用やエラーはすべて推論前に停止する。未接続時も使い方案内、ミーム、非表示・再表示、手動フォームへのリンクは使える。承認・試験範囲は [接続ノート](hiyori-ai-e2e-activation.md)。

e2e の承認済み設定。金額は e2e 全利用者の合計。

```jsonc
// env.e2e のみ
"ai": { "binding": "HIYORI_AI" },
"vars": {
  "HIYORI_AI_ENABLED": "true",
  "HIYORI_AI_TOOL_DATA_ENABLED": "true",
  "HIYORI_AI_DAILY_MICROS": "100000",
  "HIYORI_AI_MONTHLY_MICROS": "1000000",
  "HIYORI_AI_INPUT_MICROS_PER_MILLION": "51000",
  "HIYORI_AI_OUTPUT_MICROS_PER_MILLION": "335000"
}
```

予算と単価は正の整数、最大 1,000,000,000。単位は USD マイクロドル（1 USD = 1,000,000）、単価は百万トークン当たり。文字プレースホルダーでは有効にならない。現在の料金・クォータ・保存条件は運用前に公式資料と契約を確認する。無料運用を保証しない。

`ai_reservations` は要求 UUID、本人の Discord ID、予約額、時刻だけを保存。一 SQL の条件付き INSERT で日次/月次全体予算、本人ごと 5 回/直近 60 秒・30 回/UTC 日、UUID 再送を制限する。入力バイト数を課金トークンと同一視せず、モデル文脈長32,768と最大出力1,024トークンを毎回保守的に予約する。現単価では1回2,015マイクロドル。成功・失敗・結果不明のいずれでも返金しない。入力サイズは schema を含む JSON と余裕分で28,000バイトまで。実請求の集計やアカウント全体の課金上限ではなく、料金・モデル上限を前提にした開始制御である。

タイムアウトは中断 signal を送るが、プロバイダーでの処理停止や無課金は保証しない。予約は残し、自動再試行しない。利用者の「停止」も返金しない。台帳は今月と前月を保持し、既存 cron に加えて推論受付時にも古い分を削除する。e2e は cron がないので無利用中の定期削除は行わず、次回利用時に整理する。migration は `0015_smart_supernaut.sql`（台帳用索引含む）。本番適用は今回の範囲外。e2e には既に適用済みで、既存予約は消さない。

e2e Worker は `hiyori-e2e`、配信先は `https://e2e.hiyori-schedule.com`。既存の専用 D1（名前 `hiyori-invite-preview`）・専用 KV・専用 DO を使用する。旧設定にあった本番共有 KV と古い D1 ID を引き継がない。本番のトップレベル設定は変更しない。e2e は cron 無効のまま。

## モデルと検証

第一候補は `@cf/qwen/qwen3-30b-a3b-fp8`。依存の追加や Agents SDK のチャット用 DO は不要。[モデルページ](https://developers.cloudflare.com/workers-ai/models/qwen3-30b-a3b-fp8/) の `response_format` 掲載と [JSON Mode 対応一覧](https://developers.cloudflare.com/workers-ai/features/json-mode/) は別に確認する。入力形式の実対応を仮定せず、非対応や JSON 以外の出力は自動再試行せず手動フォームへ戻す。server 側 schema を常に通す。

通常の自動テストはすべて推論をモックし、認証・Origin・同意・schema・日付・予算並行性・UUID 再送・タイムアウト・セッション失効・本文非保存・UI の本人確認を検証する。

初回の実モデル合成試験は8回で終了。[記録](design/hiyori/ai-synthetic-results.json) は実ユーザー情報を含まない。初回は `json_object` で `draft` が欠落したため不受理。`json_schema` へ修正後の7回はサーバー検証を通過し、日本語会話、具体日時、相対日付、年越し、曖昧さの質問、指示逸脱の拒否、下書き修正を確認。入力5,013・出力528トークン、料金表による概算は計USD0.000432543、実請求は未確認。最大出力は各1,024、各回を最悪条件で予約した試験比較額は合計USD0.01612で、承認枠USD0.02内。初回枠は再使用しない。試験は既存接続からの公式 AI API で、実 Worker binding と認証付き公開経路の成功は証明していない。未試験の日時パターンや実機 Safari/読み上げは未確認。

公開前には、変更のレビュー、予算とデータ取扱いの合意、継続アクセス設定、承認された検証環境への migration 適用、実モデル検証、公開先とデプロイの許可が必要。コードの完成やローカルテスト合格を公開許可とみなさない。

追加承認のtool calling試験は20/20回で終了。[全記録](design/hiyori/agent-synthetic-results.json)は合成データのみ。入力24,502・出力893トークン、料金表による概算USD0.001548757（実請求未確認）。保守的予約比較額USD0.0403は承認USD0.05内。回答・集計ループ・確定／取消・編集・購読／招待一覧のツール選択を確認した。途中のツール未選択と日時の誤解釈も記録し、オフセット正規化・プロンプト修正・最大3周の継続を加えた。最終の東京19時は10:00Zへ正規化される。これは限られた標本であり、日時品質の保証ではない。変更後の動作は保存した実出力をモックとして回帰検証する。追加の実推論は別承認が必要。

公開経路の確認結果と限界は [e2eアクセス調査](hiyori-e2e-access-check.md)。実ユーザーへのログイン・再現依頼はしない。モデル単体成功と認証付き公開経路を混同せず、全体は未完了として管理する。
