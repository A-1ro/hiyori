# ﾋﾖﾘﾁｬﾝ 初期版

単一 Worker 内の Web 用マスコット。定型の使い方案内、ミーム反応、表示設定はモデルを使わない。AI 会話はログイン本人の新規イベント下書きの補助であり、作成・招待・確定を実行しない。Web の下書き入力を補助する範囲なので、既存 REST/MCP/CLI の業務操作・入力・出力・スコープは変更しない。MCP サーバーへの接続も不要。

## 構成と本人確認

- `src/client/components/Hiyori.tsx`: 起動 UI、ネイティブ dialog、定型案内、設定、タブ内会話、アカウントに結び付いた下書き受渡し。
- `src/client/pages/EventCreatePage.tsx`: AI 下書きの確認・修正。既存の認証再確認と `expectedOrganizerDiscordId` を使って本人が保存する。AI の下書きには招待・Discord チャンネルの指定を含めず、必要なら本人が既存フォームで入力する。
- `src/shared/hiyori.ts`: 入出力の allowlist schema。日付×開始時刻の全組合せを候補にする（既存フォームと同じ）。曖昧な日付・異なるタイムゾーン・意図しない組合せは確認または手動入力へ戻す。
- `src/server/services/hiyori.ts`: 一送信一推論、20 秒で待機停止、入出力上限、JSON 検証、費用予約。モデルへのツール、任意 URL 取得、業務 API 接続は存在しない。
- `GET /api/hiyori/status`: 推論設定の有無だけを返す。`POST /api/hiyori/chat`: Web セッション Cookie、同一 Origin、本人一致条件と送信確認を必要とする Web 用補助 API。クライアント指定の system メッセージや追加項目を拒否する。応答は no-store。

会話のモデル入力は送信したチャットの直近最大 6 メッセージ（各 1,000 文字まで）と定型案内・今日の日付・ブラウザのタイムゾーンだけ。既存イベント・回答・招待・セッションやページの URL/クエリは読まない。HTML として描画しない。モデルの指示逸脱は想定し、業務操作の能力を与えず、出力をフォームへ渡す前に検証する。

会話と下書きは localStorage、URL、履歴 state、DB、アプリログには保存しない。localStorage は表示設定だけ。ログアウト・アカウント切替・消去で入力と遅延応答と AI 由来のフォームを破棄する。会話を閉じるだけならタブ内に残る。

## 未接続が安全な既定値

この変更は `wrangler.jsonc` に binding や有効化設定を追加しない。予算・料金の未設定、DB migration の未適用やエラーはすべて推論前に停止する。未接続時も使い方案内、ミーム、非表示・再表示、手動フォームへのリンクは使える。

次は**後日承認された場合だけ**設定する項目の例。実際の設定ファイルではなく、現時点で有効化しない。

```jsonc
// Workers AI 接続の追加は別途承認が必要
// "ai": { "binding": "HIYORI_AI" }
// vars / local .dev.vars の項目名（値は承認後に指定）:
// HIYORI_AI_ENABLED = "true"
// HIYORI_AI_DAILY_MICROS = "<承認された日次予算>"
// HIYORI_AI_MONTHLY_MICROS = "<承認された月次予算>"
// HIYORI_AI_INPUT_MICROS_PER_MILLION = "<確認した入力単価>"
// HIYORI_AI_OUTPUT_MICROS_PER_MILLION = "<確認した出力単価>"
```

予算と単価は正の整数、最大 1,000,000,000。単位は USD マイクロドル（1 USD = 1,000,000）、単価は百万トークン当たり。文字プレースホルダーでは有効にならない。現在の料金・クォータ・保存条件は運用前に公式資料と契約を確認する。無料運用を保証しない。

`ai_reservations` は要求 UUID、本人の Discord ID、予約額、時刻だけを保存。一 SQL の条件付き INSERT で日次/月次全体予算、本人ごと 5 回/直近 60 秒・30 回/UTC 日、UUID 再送を制限する。予算は入力バイト数（テンプレート用余裕込み）と最大出力 1,024 トークン、設定した単価から保守的に予約し、成功・失敗・結果不明のいずれでも返金しない。実請求の集計ではなく、指定した単価とモデルの上限制約が正しいことを前提とする開始制御。料金改定・別料金・推論トークンの扱いを実機検証し、設定単価が不足する状態では有効化しない。

タイムアウトは中断 signal を送るが、プロバイダーでの処理停止や無課金は保証しない。予約は残し、自動再試行しない。利用者の「停止」も返金しない。台帳は今月と前月を保持し、既存の日次 cron でそれ以前を削除する。migration は `0015_smart_supernaut.sql`（台帳用索引含む）。本番適用は今回の範囲外。e2e 適用は専用 DB と既存 migration を照合してから行う。

e2e Worker は `hiyori-e2e`、配信先は `https://e2e.hiyori-schedule.com`。2026-10-25 に実環境と照合した既存の専用 D1（名前 `hiyori-invite-preview`）・専用 KV・専用 DO を使用する。旧設定にあった本番共有 KV と古い D1 ID を引き継がない。本番のトップレベル設定は変更しない。e2e は cron 無効のままで、推論 binding と予算も追加しない。

## モデルと検証

第一候補は `@cf/qwen/qwen3-30b-a3b-fp8`。依存の追加や Agents SDK のチャット用 DO は不要。[モデルページ](https://developers.cloudflare.com/workers-ai/models/qwen3-30b-a3b-fp8/) の `response_format` 掲載と [JSON Mode 対応一覧](https://developers.cloudflare.com/workers-ai/features/json-mode/) は別に確認する。入力形式の実対応を仮定せず、非対応や JSON 以外の出力は自動再試行せず手動フォームへ戻す。server 側 schema を常に通す。

テストはすべて推論をモックし、認証・Origin・同意・スキーマ・日付・予算並行性・UUID 再送・タイムアウト・セッション失効・本文非保存・UI からの本人確認を検証する。日本語品質、相対日付・年越し・月末・夏時間の意味理解、実際の JSON 互換性、課金上限の単価とトークン前提は**未検証**。これらはモデル実行の承認後に確認する。

公開前には、変更のレビュー、予算とデータ取扱いの合意、継続アクセス設定、承認された検証環境への migration 適用、実モデル検証、公開先とデプロイの許可が必要。コードの完成やローカルテスト合格を公開許可とみなさない。
